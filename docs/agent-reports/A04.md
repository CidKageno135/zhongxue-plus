## 1. Mục tiêu & Ranh giới trách nhiệm

Subagent A04 chịu trách nhiệm xây dựng tầng phòng thủ tiền xử lý (First Line of Defense) cho toàn bộ hệ thống API backend của ZhongXue V2, đảm bảo:
1. **Toàn vẹn Dữ liệu (Data Integrity):** Toàn bộ request gửi tới `/api/dictionary`, `/api/conversation`, và `/api/handwriting` phải được kiểm định nghiêm ngặt về cấu trúc dữ liệu, kiểu giá trị, độ dài chuỗi, số lượng phần tử và giới hạn số học trước khi chuyển tiếp cho động cơ xử lý lõi (A05 AI, A06 Dictionary).
2. **Chuẩn hóa Mã trạng thái HTTP (Consistent HTTP Status Codes):** Phản hồi chính xác các mã lỗi theo RFC và hợp đồng `docs/API-CONTRACT.md`:
   - `400 Bad Request`: Payload sai schema, JSON dị dạng, query thiếu, bounds không hợp lệ.
   - `404 Not Found`: Đường dẫn hoặc bản ghi không tồn tại.
   - `405 Method Not Allowed`: Sai phương thức HTTP.
   - `413 Payload Too Large`: Request body vượt quá ngưỡng an toàn (512KB cho chat, 1MB cho handwriting).
   - `415 Unsupported Media Type`: Thiếu hoặc sai header `Content-Type: application/json`.
   - `500 Internal Server Error`: Lỗi máy chủ không mong muốn.
   - `502 Bad Gateway` & `504 Gateway Timeout`: Lỗi hoặc quá hạn kết nối upstream AI/Handwriting.
3. **An toàn Bảo mật & Chống Rò rỉ Thông tin (Security & Redaction):**
   - Tuyệt đối không trả về stack traces, đường dẫn tệp hệ thống trên đĩa (`C:\...`, `/Users/...`), hoặc khóa bí mật (`AI_SOL_KEY`, `sk-...`, `Bearer ...`) trong phản hồi JSON.
   - Luôn trả về cấu trúc bao bọc chuẩn: `{ error: { code: string, message: string, details?: unknown } }`.

## 2. Chi tiết Triển khai Kỹ thuật

### 2.1 Module Lỗi HTTP (`server/errors.ts`)
- **Lớp `HttpError`:**
  Kế thừa `Error`, lưu trữ có cấu trúc các trường `statusCode: number`, `code: string`, `message: string`, và `details?: unknown`.
- **Factory Helpers chuẩn:**
  - `badRequest(message, details, code)` -> HTTP 400
  - `unauthorized(message, details, code)` -> HTTP 401
  - `forbidden(message, details, code)` -> HTTP 403
  - `notFound(message, details, code)` -> HTTP 404
  - `methodNotAllowed(message, details, code)` -> HTTP 405
  - `payloadTooLarge(message, details, code)` -> HTTP 413
  - `unsupportedMediaType(message, details, code)` -> HTTP 415
  - `badGateway(message, details, code)` -> HTTP 502
  - `serviceUnavailable(message, details, code)` -> HTTP 503
  - `gatewayTimeout(message, details, code)` -> HTTP 504
  - `internalError(message, details, code)` -> HTTP 500
- **Hàm `sendJson(res, statusCode, data)`:**
  Thiết lập `statusCode`, gắn header `Content-Type: application/json; charset=utf-8` và `Content-Length`, gửi JSON an toàn và kiểm tra cờ `res.writableEnded`.
- **Bộ khử khuẩn dữ liệu nhạy cảm (`sanitizeString` & `sanitizeDetails`):**
  - Quét và thay thế đường dẫn Windows (`C:\...`) và Unix (`/Users/...`, `/app/...`) thành `[REDACTED_PATH]`.
  - Quét và ẩn toàn bộ `Bearer <token>` thành `Bearer [REDACTED]`.
  - Nhận diện các chuỗi API Key (`sk-...`, chuỗi hex băm dài >= 24 ký tự) thành `[REDACTED_SECRET]`.
  - Đệ quy kiểm tra object `details`, tự động ẩn giá trị các key có tên nhạy cảm (`stack`, `key`, `secret`, `token`, `password`, `auth`).
- **Hàm `sendError(res, err)` & `sendError(res, statusCode, code, message, details)`:**
  Hỗ trợ cả hai kiểu gọi linh hoạt (truyền đối tượng lỗi hoặc truyền tường minh các tham số). Đảm bảo lỗi hệ thống không định kiểu (generic `Error`) khi rơi vào 500 sẽ tự động ẩn thông điệp nội bộ thành `"Internal Server Error"` và không bao giờ xuất trường `stack`.

### 2.2 Module Kiểm định Dữ liệu (`server/validation.ts`)
- **JSON Body & Content-Type:**
  - `parseJsonBody(raw: string | Buffer)`: Bắt lỗi cú pháp JSON và ném `400 INVALID_JSON`. Chặn body rỗng (`400 BAD_REQUEST`).
  - `validateJsonObject(value)`: Chặn các kiểu dữ liệu nguyên thủy (`number`, `string`, `boolean`), `null`, hoặc `Array` khi endpoint yêu cầu một JSON object.
  - `validateJsonContentType(contentType)`: Kiểm tra sự hiện diện của `application/json`, ném `415 UNSUPPORTED_MEDIA_TYPE` nếu sai.
  - `validatePayloadSize(size, maxBytes)`: Kiểm tra kích thước payload so với ngưỡng cho phép, ném `413 PAYLOAD_TOO_LARGE`.
- **Kiểm định `/api/dictionary` Query (`validateDictionaryQuery`):**
  - `q`: Hỗ trợ Hán tự, Pinyin, Tiếng Việt; cắt tỉa khoảng trắng thừa; giới hạn tối đa 200 ký tự.
  - `id`: Giới hạn tối đa 100 ký tự.
  - Bắt buộc phải có ít nhất một trong hai tham số `q` hoặc `id`; nếu thiếu cả hai ném `400 BAD_REQUEST`.
  - `mode`: Bắt buộc thuộc tập hợp `['all', 'hanzi', 'pinyin', 'vi']`, mặc định `'all'`.
  - `offset`: Bắt buộc là số nguyên không âm (`>= 0`, `<= Number.MAX_SAFE_INTEGER`), mặc định `0`. Ném 400 khi nhận NaN, số âm, hoặc số thực không nguyên.
  - `limit`: Bắt buộc là số nguyên trong khoảng `[1, 100]`, mặc định `50`. Chặn đứng giá trị âm, 0, NaN và các số cực lớn (ví dụ: `999999`).
  - Tương thích 100% với cả object query thông thường lẫn đối tượng `URLSearchParams`.
- **Kiểm định `/api/conversation` Body (`validateConversationBody`):**
  - `action`: Kiểm tra thuộc tập `['chat', 'ping', 'health']`, mặc định `'chat'`.
  - `timeoutMs`: Tự động ép trần an toàn (capping) trong khoảng `1000ms` đến `30000ms`, mặc định `12000ms`. Ném 400 nếu truyền NaN.
  - `messages`: Mảng lịch sử đối thoại, giới hạn tối đa 50 tin nhắn.
  - Từng tin nhắn kiểm tra:
    - `role`: Bắt buộc là `'user' | 'assistant' | 'system'`.
    - `content`: Bắt buộc là chuỗi, độ dài tối đa 4000 ký tự.
  - Các trường tùy chọn `unitId`, `threadId`, `roleId`, `model`, `baseUrl`, `apiKey` đều được kiểm tra kiểu dữ liệu và giới hạn ký tự an toàn.
- **Kiểm định `/api/handwriting` Body (`validateHandwritingBody`):**
  - `strokes`: Mảng bắt buộc, không rỗng, tối đa 50 nét vẽ.
  - Hỗ trợ linh hoạt cả hai định dạng nét vẽ:
    - **Format 1 (Google IME coordinate arrays):** `[xCoords[], yCoords[], tCoords[]?]` với độ dài X và Y bằng nhau.
    - **Format 2 (Point tuples/objects):** `[[x1, y1], [x2, y2]]` hoặc `[{x, y}, ...]` và tự động chuẩn hóa về `[x[], y[], t[]]` đồng nhất cho backend.
  - Tối đa 1000 điểm trên mỗi nét vẽ.
  - Tọa độ số hữu hạn, kiểm tra biên nghiêm ngặt: nằm trong khoảng `[-500, 2000]`.
  - Kiểm định `width` và `height` (10 đến 5000), `language` (tối đa 20 ký tự).
- **Trình đọc Stream Request (`readAndValidateJsonBody`):**
  Hàm tiện ích `async` giúp A02/A05 dễ dàng tiếp nhận stream Node.js `IncomingMessage`, tự động kiểm tra `Content-Type`, kiểm tra `Content-Length` header, chặn stream vượt ngưỡng bytes theo thời gian thực và phân tích JSON an toàn.

## 4. Hướng dẫn Bàn giao cho các Subagent Tiếp nối

### 4.1 Bàn giao cho Subagent A02 (Production Server & Shared Router)
- **Tích hợp đọc body:** Sử dụng `readAndValidateJsonBody(req, maxBytes)` từ `server/validation.ts` cho các tuyến POST (`/api/conversation` với `MAX_BODY_SIZE_CHAT`, `/api/handwriting` với `MAX_BODY_SIZE_HANDWRITING`).
- **Xử lý lỗi tập trung:** Bọc toàn bộ handler trong khối `try/catch` và gọi `sendError(res, error)`. `sendError` tự động nhận diện `HttpError`, mã hóa đúng status code (400, 404, 405, 413, 415, 500) và giấu hoàn toàn stack trace cũng như thông tin nhạy cảm.
- **Route 404 & 405:**
  - Route `/api/*` không tồn tại: Gọi `sendError(res, notFound('API endpoint not found', { path: req.url }))`.
  - Sai method: Gọi `sendError(res, methodNotAllowed(`Method ${req.method} not allowed on this endpoint`))`.

### 4.2 Bàn giao cho Subagent A05 (AI Connector & Guided Fallback)
- **Sử dụng DTO đã kiểm định:** Sau khi gọi `validateConversationBody(rawBody)`, A05 nhận được object sạch với:
  - `timeoutMs`: Đã được ép trần trong khoảng `[1000, 30000]` ms (mặc định 12000 ms). Dùng trực tiếp cho `AbortSignal.timeout(body.timeoutMs)`.
  - `action`: `'chat' | 'ping' | 'health'`.
  - `messages`: Mảng `ConversationTurn[]` tối đa 50 phần tử với `role` và `content` an toàn.
- **Khi Upstream lỗi hoặc quá hạn:**
  - Nếu quá hạn 12 giây: Kích hoạt guided fallback hoặc ném `gatewayTimeout('Upstream AI request timed out')`.
  - Nếu upstream trả về 5xx: Ném `badGateway('Upstream provider returned an error')` hoặc chuyển tiếp guided fallback.

### 4.3 Bàn giao cho Subagent A06 (Dictionary Engine)
- **Truy vấn từ điển:** Gọi `validateDictionaryQuery(query)` để nhận:
  - `q`: Từ khóa tìm kiếm đã được trim, độ dài <= 200 ký tự.
  - `id`: Mã bản ghi cần tra cứu chi tiết.
  - `mode`: Một trong 4 giá trị `'all' | 'hanzi' | 'pinyin' | 'vi'`.
  - `offset`: Số nguyên `>= 0`.
  - `limit`: Số nguyên từ `1` đến `100` (mặc định `50`).
- **Xử lý kết quả:** Nếu tra cứu theo `id` mà không tìm thấy bản ghi, ném `notFound(`Dictionary entry with ID ${id} not found`)`.

### 4.4 Bàn giao cho Subagent A16 (QA API Security)
- Sử dụng các fixture và kịch bản dị dạng đã xây dựng tại `tests/api-validation.test.ts` để kiểm thử xuyên suốt (end-to-end integration) trên máy chủ Node.js production.
- Đảm bảo xác thực rằng không có phản hồi nào làm rò rỉ token hoặc trả về trang HTML cho các tuyến API.
