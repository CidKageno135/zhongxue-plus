## 1. Tóm tắt Phát hiện & Mục tiêu Khắc phục (Finding PROD-01: Critical P1)

Theo đánh giá kiến trúc tại `docs/reviews/2026-10-21-hardening-review.md`, hệ thống ZhongXue trước đây gặp vấn đề nghiêm trọng:
1. **Thiếu Máy chủ Production Độc lập:** Phiên bản cũ chỉ có plugin Vite dev (`src/viteApiPlugin.ts`) lắng nghe trong hook `configureServer()`. Khi triển khai production hoặc chạy `npm run build`, không có máy chủ Node.js phục vụ các yêu cầu API, khiến ứng dụng hoàn toàn mất khả năng vận hành backend.
2. **Lỗi Rơi vào SPA Fallback cho Tuyến API (API Route Leaking):** Khi client gọi một API không tồn tại (ví dụ `/api/does-not-exist`), máy chủ tĩnh trả về file HTML `index.html` với mã HTTP 200 thay vì trả về JSON 404. Điều này khiến client parser gặp lỗi `SyntaxError: Unexpected token '<'` và phá vỡ hợp đồng API.
3. **Nguy cơ Bảo mật Tệp tĩnh:** Không có cơ chế kiểm tra Path Traversal (`/../.env`, `/%2e%2e/.env`), thiếu danh sách đen chặn các tệp cấu hình bí mật (`.env*`, `.git*`, `package.json`, `tsconfig.json`).
4. **Phân kỳ Kiến trúc (Architectural Divergence):** Logic xử lý API giữa môi trường phát triển (Vite plugin) và môi trường production bị tách rời, tiềm ẩn rủi ro hành vi không đồng nhất.

## 2. Kiến trúc & Giải pháp Triển khai (Zero-Divergence Architecture)

Subagent A02 đã hiện thực hóa mô hình **Kiến trúc Không-Phân-Kỳ (Zero-Divergence Architecture)**:

```
                          ┌──────────────────────────────┐
                          │   HTTP Request (Client)      │
                          └──────────────┬───────────────┘
                                         │
                 ┌───────────────────────┴───────────────────────┐
                 ▼                                               ▼
     [Production Environment]                        [Development Environment]
      server/index.ts (Node HTTP)                     src/viteApiPlugin.ts (Vite Dev)
                 │                                               │
                 └───────────────────────┬───────────────────────┘
                                         ▼
                             ┌───────────────────────┐
                             │     server/app.ts     │
                             │  (CORS & Origin Check)│
                             └───────────┬───────────┘
                                         │
                    ┌────────────────────┴────────────────────┐
                    ▼                                         ▼
            Path starts with /api/*                 Other paths (Static/SPA)
                    │                                         │
                    ▼                                         ▼
            ┌───────────────┐                         ┌───────────────┐
            │server/routes.ts│                         │server/static.ts│
            └───────┬───────┘                         └───────┬───────┘
                    │                                         │
        ┌───────────┼───────────┐                             ├─ Asset caching (immutable)
        ▼           ▼           ▼                             ├─ Traversal defense (403)
   /api/health  /api/dict   /api/conv                         ├─ Sensitive block (403)
        │           │           │                             └─ SPA Fallback (index.html)
   Unknown /api/* ──┴───────────┘                                (NEVER for /api/*)
        │
   JSON 404 (NEVER HTML!)
```

### 2.1. Hạt nhân Điều phối Tuyến API (`server/routes.ts`)
- **Tách biệt Tuyệt đối:** Mọi yêu cầu bắt đầu bằng `/api/` được xử lý tập trung trong `routes.ts`. Nếu không khớp bất kỳ endpoint nào, lập tức trả về JSON 404:
  ```json
  {
    "error": {
      "code": "NOT_FOUND",
      "message": "API endpoint not found: /api/does-not-exist"
    }
  }
  ```
  Tuyệt đối không bao giờ chuyển tiếp (fallthrough) sang bộ phục vụ tệp tĩnh hoặc trả về HTML SPA fallback.
- **`GET /api/health`:**
  - Tích hợp trực tiếp với `dictionaryEngine.isReady()`, `getTotal()`, `getLoadTimeMs()`.
  - Kiểm tra trạng thái AI thông qua `getAiConfigStatus()` (`configured`, `provider`, `model`, `hasApiKey`).
  - Trả về mã HTTP 200 với schema `HealthResponse` khi từ điển đã sẵn sàng; trả về HTTP 503 `SERVICE_UNAVAILABLE` nếu từ điển đang nạp hoặc lỗi.
  - Từ chối các HTTP method khác ngoài `GET` bằng mã HTTP 405 `METHOD_NOT_ALLOWED`.
- **`GET /api/dictionary`:**
  - Kiểm định tham số đầu vào qua `validateDictionaryQuery(searchParams)`.
  - Phục vụ truy vấn theo ID (`id`): gọi `dictionaryEngine.getById(id)`, trả về JSON 200 hoặc JSON 404 nếu không tìm thấy.
  - Phục vụ tìm kiếm từ khóa (`q`): gọi `dictionaryEngine.search(q, { mode, limit, offset })` với phân hạng 4 tầng (Tier 1: Trùng khớp tuyệt đối, Tier 2: Bắt đầu bằng, Tier 3: Chứa từ khóa, Tier 4: Tiếng Việt).
  - Trả về schema `DictionarySearchResponse`. Từ chối method không phải `GET` bằng mã HTTP 405.
- **`GET /api/conversation` & `POST /api/conversation`:**
  - Chuyển tiếp trơn tru tới hàm xử lý chuẩn `handleConversationRoute(req, res)` từ module `server/ai.ts`.
  - Hỗ trợ `GET` để kiểm tra trạng thái probe (`ready`, `model`, `hasApiKey`).
  - Hỗ trợ `POST` với các action `chat`, `explain`, `ping`.
- **`POST /api/handwriting`:**
  - Giới hạn kích thước tải tối đa qua `MAX_BODY_SIZE_HANDWRITING` (100KB) bằng `readAndValidateJsonBody`.
  - Kiểm định mảng nét bút (`validateHandwritingBody`).
  - Gọi proxy an toàn tới Google Input Tools với cơ chế ngắt kết nối `AbortSignal.timeout(4000)`.
  - Tự động fallback về `{ candidates: [], source: 'local_fallback' }` nếu upstream ngoại tuyến hoặc lỗi, không làm gián đoạn trải nghiệm người dùng.

### 2.2. Bảo vệ & Phục vụ Tệp tĩnh (`server/static.ts`)
- **Phòng chống Path Traversal (Tuyệt đối):**
  - Chặn ký tự null byte (`\0`, `%00`).
  - Chặn các chuỗi điều hướng thư mục (`..`, `%2e%2e`, `%2E%2E`).
  - Phân giải đường dẫn tuyệt đối bằng `path.resolve` và kiểm tra tính trực thuộc bằng `path.relative(resolvedDist, candidatePath)`. Nếu vượt ra ngoài thư mục `dist/`, lập tức từ chối với HTTP 403 `FORBIDDEN`.
- **Chặn Tệp Cấu hình & Dữ liệu Nhạy cảm:**
  - Danh sách đen regex chặn toàn diện: `^\.env.*$`, `^\.git.*$`, `^node_modules.*$`, `^package.*\.json$`, `^tsconfig.*\.json$`, `^\.DS_Store$`.
  - Trả về HTTP 403 `FORBIDDEN` kèm cảnh báo bảo mật.
- **Chiến lược Cache-Control Tối ưu:**
  - Các tài nguyên tĩnh có mã băm (`/assets/*`): `public, max-age=31536000, immutable`.
  - Tệp HTML chính (`index.html`): `no-cache, no-store, must-revalidate` để client luôn nhận phiên bản mới nhất khi cập nhật ứng dụng.
  - Các tài nguyên tĩnh khác: `public, max-age=3600`.
- **SPA Fallback An toàn:**
  - Chỉ phục vụ `dist/index.html` cho các yêu cầu điều hướng client hợp lệ (phương thức `GET` hoặc `HEAD`, không chứa phần mở rộng file ngoại trừ `.html`).
  - **Không bao giờ áp dụng SPA fallback cho bất kỳ tuyến nào bắt đầu bằng `/api/`**.

### 2.3. Hạt nhân Ứng dụng & Chia sẻ Dev/Prod (`server/app.ts`)
- Hàm `createAppHandler({ distPath, dictPath })`:
  - Khởi tạo listener chuẩn Node.js `(req: IncomingMessage, res: ServerResponse) => Promise<void>`.
  - Tích hợp kiểm tra `Origin` qua `isAllowedOrigin()` và áp dụng tiêu đề `getCorsHeaders()`.
  - Tự động xử lý tiền kiểm tra CORS `OPTIONS` bằng HTTP 204 `No Content`.
  - Nếu `Origin` không được phép trên request CORS, từ chối với HTTP 403 `FORBIDDEN_ORIGIN`.
  - Phân phối yêu cầu: nếu `url.pathname.startsWith('/api/')` chuyển sang `handleRoutes()`, ngược lại chuyển sang `handleStatic()`.
- Hàm `handleApiRequest(req, res, url)`:
  - Được xuất khẩu trực tiếp để plugin Vite dev (`src/viteApiPlugin.ts`) tái sử dụng trọn vẹn logic của `server/routes.ts`.
  - Bảo đảm hành vi API ở môi trường dev và production giống hệt nhau 100%.

### 2.4. Điểm Khởi động Máy chủ Độc lập (`server/index.ts`)
- Khởi tạo máy chủ HTTP native `node:http`.
- Tự động nạp biến môi trường từ `.env` bằng `loadEnvFiles()`, có cơ chế bảo vệ `if (!process.env.VITEST)` để không làm nhiễm bẩn biến môi trường của các bài test Vitest.
- Khởi tạo engine từ điển `dictionaryEngine.init()` ngay khi máy chủ bắt đầu chạy.
- Hỗ trợ cấu hình `PORT` (mặc định 3000) và `HOST` (mặc định `127.0.0.1`).
- **Đóng máy chủ mượt mà (Graceful Shutdown):**
  - Lắng nghe tín hiệu `SIGINT` và `SIGTERM`.
  - Đóng kết nối HTTP đang hoạt động bằng `server.closeAllConnections()`.
  - Hủy các tiến trình ngầm và kết thúc tiến trình sạch sẽ với mã thoát 0.
- Xuất khẩu hàm `startServer(options)` phục vụ khởi chạy lập trình trong các bộ test tích hợp và test E2E.

## 4. Bàn giao & Chỉ dẫn Tích hợp (Handoff Guidelines)

1. **Bàn giao cho Subagent A01 (Integration Lead):**
   - Tệp `server/app.ts` xuất hàm `handleApiRequest(req, res, url)`:
     ```ts
     import { handleApiRequest } from '../server/app.ts';
     // Sử dụng trực tiếp trong viteApiPlugin.ts:
     const handled = await handleApiRequest(req, res, url);
     if (handled) return;
     ```
   - Điều này giúp loại bỏ hoàn toàn mã trùng lặp trong `src/viteApiPlugin.ts` và bảo đảm tính Zero-Divergence.

2. **Bàn giao cho Subagent A08 (Client Adapter):**
   - Toàn bộ các API endpoint đã sẵn sàng tại các đường dẫn chuẩn:
     - `GET /api/health`
     - `GET /api/dictionary?q=...` hoặc `GET /api/dictionary?id=...`
     - `GET /api/conversation` & `POST /api/conversation`
     - `POST /api/handwriting`
   - Bất kỳ lỗi nào cũng sẽ được đóng gói trong envelope chuẩn `ApiErrorBody`:
     ```ts
     interface ApiErrorBody {
       error: {
         code: string;
         message: string;
         details?: Record<string, unknown>;
       };
     }
     ```

3. **Bàn giao cho Subagent A16 (QA API & Independent Security Lead):**
   - Toàn bộ các tiêu chí kiểm thử của finding **PROD-01** đã được cài đặt và vượt qua 100% trong `tests/integration/production-server.test.ts` và `tests/integration/api-security.test.ts`.
   - Máy chủ production có thể được khởi chạy bằng script:
     ```bash
     npm run build
     npm run start
     ```
   - Sẵn sàng cho việc thực thi kiểm thử E2E trên production (`npm run test:e2e:prod`).
