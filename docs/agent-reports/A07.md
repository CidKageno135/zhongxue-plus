## 1. Mục tiêu & Ranh giới trách nhiệm

Subagent A07 chịu trách nhiệm xây dựng module thuần TypeScript `src/domain/searchNormalization.ts` phục vụ đồng thời cho cả Client (Browser) và Server (Node.js), loại bỏ 100% phụ thuộc vào React, DOM, hoặc Node runtime APIs:

1. **Khắc phục lỗi tìm kiếm Pinyin và Tiếng Việt (Zero Search Divergence):**
   - Trước đây: `學生`, `xuesheng`, `học sinh` có kết quả; nhưng `xuéshēng` và `hoc sinh` trả 0 kết quả do thiếu bộ chuẩn hóa ngữ âm và dấu tiếng Việt hai chiều.
   - Xử lý triệt để các biến thể thanh điệu Pinyin: có dấu (`xuéshēng`), có số thanh (`xue2 sheng1`, `xue2sheng1`), không dấu (`xuesheng`).
   - Xử lý triệt để tiếng Việt có dấu (`học sinh`, `Đài Loan`, `tiếng Việt`) và không dấu (`hoc sinh`, `dai loan`, `tieng viet`).
2. **Quy tắc bảo vệ âm ngữ học `ü` vs `u` ("Không coi mọi chữ u giống ü"):**
   - Trong tiếng Trung, `lù` (路, 4th tone) và `lǜ` (綠, 4th tone umlaut) là hai âm vị khác biệt hoàn toàn; `nù` (怒) và `nǚ` (女) là hai âm vị khác biệt hoàn toàn.
   - Chuẩn hóa thống nhất `ü`, `u:`, `v` về `v` trong chuỗi sạch để không bao giờ để `lù` khớp nhầm `lǜ` hoặc `nu` khớp nhầm `nv` (nǚ).
3. **Chuẩn hóa Unicode toàn diện:**
   - Xử lý bình đẳng giữa dạng dựng sẵn (Precomposed NFC) và dạng tổ hợp (Decomposed NFD).
   - Xử lý các chữ cái tiếng Việt đặc biệt: `đ`, `Đ`, `a, ă, â, e, ê, i, o, ô, ơ, u, ư, y` cùng 5 thanh điệu (sắc, huyền, hỏi, ngã, nặng).
4. **Hàm thuần (Pure Functions) & Độc lập hoàn toàn:**
   - Không import bất kỳ package npm bên ngoài hay module Node.js (`fs`, `path`, `zlib`) nào.
   - Sẵn sàng tích hợp trực tiếp vào Động cơ từ điển Backend (`server/dictionary.ts` — A06) và Bộ điều hợp Client (`src/services/api.ts` — A08, `src/views/DictionaryView.tsx` — A10).

## 2. Chi tiết Triển khai Kỹ thuật (`src/domain/searchNormalization.ts`)

Module cung cấp các hàm xuất khẩu (exported functions) và kiểu dữ liệu chuẩn:

### 2.1 Các Interface DTO cốt lõi
```typescript
export interface NormalizedPinyin {
  original: string;   // Chuỗi gốc được trim
  numbered: string;   // Pinyin số thanh điệu ('xue2sheng1', 'lu4', 'lv4', 'nv3')
  clean: string;      // Pinyin chữ cái sạch không dấu, không số, đã chuyển ü/u: -> v ('xuesheng', 'lu', 'lv', 'nv')
}

export interface NormalizedSearchQuery {
  raw: string;         // Truy vấn gốc
  clean: string;       // Chuỗi thường, chuẩn hóa NFC, khoảng trắng đơn
  viClean: string;     // Chuỗi tiếng Việt bóc sạch dấu thanh và đ/Đ -> d
  pinyinClean: string; // Chuỗi Pinyin sạch dùng so khớp ngữ âm
  isHanzi: boolean;    // true nếu truy vấn chủ yếu là chữ Hán
}
```

### 2.2 Chi tiết 6 Hàm Thuần Xuất Khẩu

#### 1. `normalizeVietnamese(text: string, options?: { preserveCase?: boolean }): string`
- Đưa văn bản về dạng chuẩn hóa NFD.
- Chuyển đổi an toàn `ü`, `u:`, `u\u0308` thành `v` để tránh việc bóc tách dấu diaeresis làm biến dạng âm Pinyin sang `u`.
- Bóc tách toàn bộ ký tự dấu tổ hợp tiếng Việt trong dải `[\u0300-\u036f]`.
- Thay thế `đ/Đ` thành `d/D` (hoặc `d` khi `preserveCase: false`).
- Rút gọn chuỗi khoảng trắng và trim đầu/cuối.
- Ví dụ:
  - `normalizeVietnamese('học sinh')` ➔ `'hoc sinh'`
  - `normalizeVietnamese('Đài Loan')` ➔ `'dai loan'`
  - `normalizeVietnamese('Đài Loan', { preserveCase: true })` ➔ `'Dai Loan'`
  - `normalizeVietnamese('tiếng việt')` ➔ `'tieng viet'`

#### 2. `convertToneMarksToNumbered(text: string): string`
- Bảng ánh xạ `TONE_CHAR_MAP` bao phủ toàn bộ nguyên âm mang dấu thanh điệu chuẩn quốc tế:
  - Thanh 1 (Macron): `ā, ē, ī, ō, ū, ǖ`
  - Thanh 2 (Acute): `á, é, í, ó, ú, ǘ, ế, ń`
  - Thanh 3 (Caron): `ǎ, ě, ǐ, ǒ, ǔ, ǚ, ň`
  - Thanh 4 (Grave): `à, è, ì, ò, ù, ǜ, ề, ǹ`
- Quy tắc vị trí số thanh điệu cuối âm tiết (Syllable Coda Placement):
  1. Nguyên âm nhị trùng ngậm (Diphthong offglide): `hǎo` ➔ `hao3`, `lèi` ➔ `lei4`, `lái` ➔ `lai2`.
  2. Âm cuối mũi/uốn lưỡi (Nasal/Rhotic Coda): `shēng` ➔ `sheng1`, `jiàn` ➔ `jian4`, `zhōng` ➔ `zhong1`, `tiān` ➔ `tian1`.
  3. Từ ghép liền không dấu cách: `xuéshēng` ➔ `xue2sheng1`, `běijīng` ➔ `bei3jing1`, `tàiwān` ➔ `tai4wan1`.
  4. Chuẩn hóa `ü` và `u:` thành `v`: `lù` ➔ `lu4`, `lǜ` ➔ `lv4`, `nǚ` ➔ `nv3`, `nu:3` ➔ `nv3`, `lu:4` ➔ `lv4`.
  5. Bảo toàn nguyên vẹn chữ Hán: `學生` ➔ `學生`.

#### 3. `normalizePinyin(text: string): NormalizedPinyin`
- Trả về bộ ba thuộc tính:
  - `original`: chuỗi gốc đã trim.
  - `numbered`: chuỗi số thanh điệu chữ thường.
  - `clean`: chuỗi ký tự sạch không thanh số, loại bỏ dấu nối, dấu gạch dưới, khoảng trắng và dấu câu, bảo toàn chữ Hán.
- Ví dụ kiểm nghiệm:
  - `'xuéshēng'` ➔ `{ clean: 'xuesheng', numbered: 'xue2sheng1' }`
  - `'xue2 sheng1'` ➔ `{ clean: 'xuesheng', numbered: 'xue2 sheng1' }`
  - `'xue2sheng1'` ➔ `{ clean: 'xuesheng', numbered: 'xue2sheng1' }`
  - `'lù'` ➔ `{ clean: 'lu', numbered: 'lu4' }`
  - `'lǜ'` ➔ `{ clean: 'lv', numbered: 'lv4' }` (Khác biệt tuyệt đối với `lu`!)
  - `'nǚ'` ➔ `{ clean: 'nv', numbered: 'nv3' }`
  - `'nu:3'` ➔ `{ clean: 'nv', numbered: 'nv3' }`

#### 4. `isHanziText(text: string): boolean`
- Nhận diện các ký tự thuộc khối CJK Unified Ideographs (`\u4e00-\u9fff`) và Extension A (`\u3400-\u4dbf`).
- Bỏ qua khoảng trắng và dấu câu khi phân loại.
- Kết quả: `學生`, `台灣`, `你好`, `臺北` đều trả về `true`; `xuesheng`, `học sinh` trả về `false`.

#### 5. `normalizeSearchQuery(query: string): NormalizedSearchQuery`
- Phân rã từ khóa tìm kiếm người dùng nhập thành 5 chiều phục vụ bộ lọc tìm kiếm tốc độ cao:
  - `raw`: `'xuéshēng'`
  - `clean`: `'xuéshēng'`
  - `viClean`: `'xuesheng'`
  - `pinyinClean`: `'xuesheng'`
  - `isHanzi`: `false`

#### 6. `matchesQuery(target: string, query: string): boolean`
- Thuật toán so khớp đa chiều thông minh kết hợp 4 tầng:
  1. **Khớp Chữ Hán:** Nếu query là chữ Hán, so khớp chuỗi chữ Hán trên target.
  2. **Khớp Chính xác:** So khớp chuỗi con không phân biệt hoa thường trên chuỗi đã chuyển `u:` ➔ `v`.
  3. **Khớp Ngữ âm Pinyin:**
     - So khớp Pinyin có số thanh (`tNumNoSpace.includes(qNumNoSpace)`).
     - So khớp Pinyin âm sạch (`tPinyin.clean.includes(qPinyin.clean)`).
     - Phân định rạch ròi giữa `lu` và `lv`: `matchesQuery("路 [lu4]", "lù") === true`, `matchesQuery("路 [lu4]", "lǜ") === false`.
  4. **Khớp Tiếng Việt Hai Chiều:**
     - Người dùng gõ không dấu (`hoc sinh`, `dai loan`, `tieng viet`) khớp mục từ có dấu (`học sinh`, `Đài Loan`, `tiếng Việt`).
     - Mục từ không dấu khớp với truy vấn có dấu.
     - So khớp linh hoạt cả khi có hoặc không có khoảng trắng (`hocsinh` khớp `học sinh`).

A06 có thể nạp trực tiếp module A07 để thay thế hoặc tăng cường logic chuẩn hóa trong `DictionaryEngine`:

```typescript
import {
  normalizeVietnamese,
  normalizePinyin,
  normalizeSearchQuery,
  matchesQuery,
  isHanziText
} from '../src/domain/searchNormalization';

// 1. Khi lập chỉ mục CC-CEDICT:
const pinyinNorm = normalizePinyin(entry.pinyin); // lu:4 -> numbered: 'lv4', clean: 'lv'
const defsViClean = entry.definitions.map(d => normalizeVietnamese(d)).join(' ');
const searchIndex = `${entry.traditional} ${entry.simplified} ${entry.pinyin} ${pinyinNorm.clean} ${pinyinNorm.numbered} ${entry.definitions.join(' ')} ${defsViClean}`;

// 2. Khi tra cứu truy vấn người dùng:
const qNorm = normalizeSearchQuery(query);
// qNorm.isHanzi -> Fast path tìm kiếm tradMap / simpMap
// qNorm.pinyinClean -> Tìm kiếm pinyinExactMap
// matchesQuery(targetText, query) -> Bộ lọc fallback chính xác tuyệt đối
```

### 4.2 Dành cho Subagent A08 — Client API & Tra cứu Cục bộ (`src/services/api.ts`)
A08 và A10 (`DictionaryView.tsx`) có thể nhập trực tiếp các hàm từ `src/domain/searchNormalization.ts` mà không sợ phình to bundle kích thước hay lỗi môi trường trình duyệt:

```typescript
import { normalizeVietnamese, normalizePinyin, matchesQuery } from '../domain/searchNormalization';

// Lọc từ vựng đã lưu trong sổ tay SRS ngoại tuyến:
export function searchLocalWords(words: SavedWord[], query: string): SavedWord[] {
  return words.filter(w =>
    matchesQuery(`${w.hanzi} ${w.pinyin} ${w.meaning}`, query)
  );
}
```
