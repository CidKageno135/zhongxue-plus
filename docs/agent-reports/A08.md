## 1. Mục tiêu & Vấn đề Cần Khắc Phục (Core Objectives)

Trong kiến trúc v1 trước đây, tầng giao tiếp API của máy khách tồn tại các khiếm khuyết lớn:
1. **Phân kỳ kiến trúc cổng 3001 (`BACKEND_BASE = 'http://127.0.0.1:3001'`):** Khi chạy production độc lập (`npm run start`), máy chủ phục vụ cả static assets lẫn API trên cùng một origin (`127.0.0.1:3000`). Việc client âm thầm fallback sang port `:3001` gây lỗi kết nối vô ích (connection refused) hoặc tạo ra sự phân kỳ môi trường không thể kiểm soát.
2. **Lỗi nhận diện sai trạng thái Backend (SPA HTML 200 False Positive):** Khi chạy `vite preview` hoặc máy chủ web chưa bật API, mọi request `/api/health` đều trả về HTTP 200 nhưng nội dung là trang HTML của Single Page Application (`<!doctype html>...`). Code cũ chỉ kiểm tra `res.ok` nên lập tức kết luận backend đang "online" với số lượng từ vựng giả lập `122595`, dẫn đến các lệnh tra cứu sau đó thất bại dây chuyền.
3. **Mất kết nối Pinyin có dấu và Tiếng Việt không dấu khi ngoại tuyến:** Khi mất mạng, hàm tra cứu dự phòng cục bộ `searchWords` sử dụng bộ lọc chuỗi sơ sài, khiến các từ khóa như `xuéshēng` (Pinyin có dấu thanh) hoặc `hoc sinh` (tiếng Việt bỏ dấu) trả về 0 kết quả mặc dù từ điển bài học có từ này.
4. **Thiếu cơ chế hủy yêu cầu (`AbortSignal`) trên giao diện:** Người dùng bấm nút gửi tin nhắn AI hoặc vẽ chữ Hán rồi chuyển tab/bấm Hủy, request vẫn âm thầm chạy ngầm và ghi đè trạng thái UI muộn hơn, gây race conditions.

Subagent A08 đã tái cấu trúc toàn diện `src/services/api.ts` để đáp ứng 100% bản hợp đồng `docs/API-CONTRACT.md` với nguyên tắc không phân kỳ (Zero-Divergence).

## 2. Chi tiết Triển khai Kỹ thuật (`src/services/api.ts`)

### 2.1 Loại bỏ triệt để Port 3001 — Chuẩn hóa Cùng-Origin (Same-Origin Relative Endpoints)

Toàn bộ hằng số `BACKEND_BASE` và hàm `fetchWithFallback` cũ đã được loại bỏ hoàn toàn:

| Thuộc tính | Kiến trúc v1 (Cũ) | Kiến trúc v2 (Subagent A08) |
|---|---|---|
| **Base URL** | `http://127.0.0.1:3001` (hardcode) | Cùng-origin tương đối: `/api/...` |
| **Cơ chế gọi API** | Gọi relative, nếu lỗi retry sang `:3001` | Gọi trực tiếp qua helper `apiFetch(path, options)` gắn sẵn header `Accept: application/json` |
| **Môi trường dev** | Phụ thuộc plugin dev chuyển hướng | Vite plugin proxy cùng origin |
| **Môi trường prod** | Thất bại do không có tiến trình `:3001` | Standalone server Node.js mount `/api/*` trên port 3000 |

```typescript
async function apiFetch(path: string, options?: RequestInit): Promise<Response> {
  const headers = new Headers(options?.headers);
  if (!headers.has('Accept')) {
    headers.set('Accept', 'application/json');
  }

  return fetch(path, {
    ...options,
    headers
  });
}
```

### 2.2 Kiểm tra Trạng thái Sẵn sàng của Backend (`checkBackendHealth`)

Hàm `checkBackendHealth` áp dụng cơ chế xác thực 3 lớp nghiêm ngặt nhằm triệt tiêu hoàn toàn hiện tượng coi trang HTML SPA fallback là backend sẵn sàng:

1. **Lớp 1 — Trạng thái HTTP:** Bắt buộc `res.ok` (HTTP 200..299).
2. **Lớp 2 — Tiêu đề MIME Type:** Bắt buộc header `content-type` phải chứa chuỗi `application/json`. Nếu là `text/html`, lập tức trả về `online: false` mà không cần thử phân tích JSON.
3. **Lớp 3 — Cấu trúc dữ liệu JSON (Schema Contract):**
   - Phải là JSON Object hợp lệ.
   - Bắt buộc `status === 'ok'`.
   - Bắt buộc `dictionary.loaded === true`.
   - Đọc số lượng mục từ thực tế `totalEntries` trực tiếp từ phản hồi backend (`data.dictionary.totalEntries`, ví dụ: `122596`), tuyệt đối không hardcode.
   - Nếu `status === 'degraded'` hoặc nạp thất bại, trả về `online: false, totalEntries: 40`.

### 2.3 Tích hợp Chuẩn hóa Tìm kiếm A07 vào Bộ Tìm kiếm Dự phòng Cục bộ (`searchLocalLessons`)

Khi backend ngoại tuyến hoặc mạng gặp sự cố, `searchDictionary` tự động chuyển tiếp sang `searchLocalLessons`:

- **Nguồn dữ liệu:** Kết hợp kho từ vựng bài học chuẩn (`getAllKnownWords()` từ `src/domain/learning.ts` — bao gồm 16 bài học chính quy và từ vựng mở rộng của người dùng) cùng bộ từ vựng nền tảng ngoại tuyến (`FOUNDATIONAL_FALLBACK_WORDS` bao gồm `學生`, `老師`, `臺灣`, `華語`).
- **Tích hợp module A07 (`src/domain/searchNormalization.ts`):**
  - Khớp Pinyin có dấu thanh điệu: `xuéshēng` khớp `學生` (pinyin: `xuéshēng`).
  - Khớp Pinyin có số thanh: `xue2 sheng1`, `xue2sheng1` khớp `學生`.
  - Khớp Pinyin âm sạch: `xuesheng` khớp `學生`.
  - Khớp tiếng Việt không dấu: `hoc sinh` khớp `學生` (nghĩa: `Học sinh, sinh viên`).
  - Khớp tiếng Việt có dấu: `học sinh` khớp `學生`.
  - Bảo vệ âm ngữ học `ü` vs `u`: phân biệt rạch ròi `lu` và `lv` theo quy chuẩn ngữ âm tiếng Trung.
- **Hỗ trợ 4 chế độ tra cứu (`mode`):**
  - `mode === 'hanzi'`: Tra cứu chuyên biệt theo Hán tự.
  - `mode === 'pinyin'`: Chỉ so khớp theo trường phiên âm Pinyin.
  - `mode === 'vi'`: Chỉ so khớp theo giải nghĩa tiếng Việt.
  - `mode === 'all'`: So khớp đa tầng trên chuỗi tổ hợp `Hán tự [Pinyin] /Nghĩa/`.
- **Xếp hạng kết quả thông minh (Weighted Scoring):** Ưu tiên Hán tự khớp tuyệt đối (100 điểm) $\to$ Pinyin sạch khớp tuyệt đối (90 điểm) $\to$ Tiếng Việt khớp tuyệt đối (80 điểm) $\to$ Khớp tiền tố (50/40 điểm).
- **Phân trang cục bộ chuẩn xác:** Áp dụng `offset` và `limit` chính xác trên mảng kết quả, trả về `total` trung thực theo toàn bộ danh sách khớp.

### 2.4 Trợ lý Hội thoại AI Linh hoạt & Hủy Yêu cầu Chủ động (`sendAiMessage`)

Được thiết kế để vừa tương thích ngược 100% với các component hiện tại (như `src/views/AiChatView.tsx`), vừa hỗ trợ cú pháp hiện đại:

- **Hỗ trợ Đa Chữ Ký (Overloaded Signatures):**
  1. Dạng tham số đối tượng (hiện đại): `sendAiMessage(input, options?: SendAiMessageOptions, signal?: AbortSignal)`
  2. Dạng tham số vị trí (tương thích ngược): `sendAiMessage(message, unitId, history, threadId, roleId, modelCandidate, signal)`
- **Hỗ trợ hủy request chủ động qua `AbortSignal`:**
  - Nếu `signal` đã bị abort trước hoặc trong khi gọi fetch, hàm lập tức ném ra lỗi `AbortError` (hoặc `DOMException('The operation was aborted', 'AbortError')`).
  - Nhờ đó, giao diện biết rằng người dùng chủ động bấm "Hủy" hoặc chuyển bài học, **không kích hoạt phản hồi cục bộ ngoài ý muốn**.
- **Nhận biết trạng thái Live AI vs Guided Fallback:**
  - Nếu kết nối server thành công: trả về DTO `ConversationReply` với `mode: 'ai'` (hoặc `mode: 'guided'` do máy chủ điều phối).
  - Nếu mạng ngoại tuyến hoặc server lỗi: kích hoạt `simulateLocalAiReply` cục bộ, gắn nhãn rõ ràng `mode: 'guided'` kèm `meta.fallbackReason = 'offline'` và ghi chú hướng dẫn `meta.guidanceNote`.

### 2.5 Nhận diện Viết tay Chữ Hán An toàn & Fallback Hình học (`recognizeHandwriting`)

- **Kiểm định đầu vào nghiêm ngặt:** Hàm `isValidStrokeArray` kiểm tra mảng nét vẽ; nếu rỗng hoặc tọa độ không hợp lệ, lập tức trả về mảng rỗng `[]` mà không gửi request mạng thừa thãi.
- **Hỗ trợ `AbortSignal`:** Hủy tức thì tác vụ nhận diện khi người dùng xóa bảng vẽ canvas hoặc bắt đầu vẽ nét mới.
- **Dự phòng bộ phân loại nét hình học client (`fallbackClientHandwriting`):**
  - Khi mất kết nối mạng hoặc API upstream trả về mảng rỗng: kích hoạt thuật toán phân tích góc hướng vector và tỷ lệ `dx/dy` để phân loại các nét cơ bản (Hoành - H, Thụ - S, Phẩy - P, Mác - N, Điểm - D, Chiết - Z, Hất - T).
  - So khớp với 75 chữ Hán thông dụng trong đời sống Đài Loan (ví dụ: nét ngang đơn $\to$ `一`, nét phẩy-mác $\to$ `人`, `八`, `入`, nét gập $\to$ `中`, `口`).
