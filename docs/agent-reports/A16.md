## 1. Mục tiêu & Ranh giới trách nhiệm

Subagent A16 đóng vai trò là chốt chặn bảo mật và kiểm định chất lượng độc lập (Independent Security QA Gate) trước khi tích hợp hệ thống. Toàn bộ các bài kiểm thử của A16 được thiết kế độc lập, không dựa vào mock nông của Vitest (`vi.mock`), mà thực thi yêu cầu HTTP trực tiếp trên tiến trình máy chủ với các mục tiêu cụ thể:

1. **Khóa chặt Ranh giới Xác thực & Chống Rò rỉ Khóa (SEC-01 Verification):**
   - Sử dụng các khóa sentinel giả định (`sk-sentinel-sol-secret-never-leak-998877`, `sk-sentinel-deepseek-secret-never-leak-665544`) bơm vào biến môi trường.
   - Gửi yêu cầu với `baseUrl: "https://attacker.evil.com"` mà không có `apiKey` ➔ Xác minh server không bao giờ chuyển tiếp khóa môi trường; tự động chuyển sang guided fallback hoặc báo lỗi ủy quyền an toàn.
   - Gửi yêu cầu với hostname lừa đảo chứa chuỗi con `agentrouter` (như `https://agentrouter.org.evil.com` hoặc `https://evil-attacker.com/agentrouter.org`) ➔ Xác minh kiểm tra allowlist tên miền chính xác 100%, không bị đánh lừa bởi substring.
   - Kiểm tra chuyển hướng HTTP (HTTP 301/302 Redirect): Xác minh cấu hình `redirect: 'manual'` chặn đứng việc rò rỉ `Authorization: Bearer <token>` sang máy chủ đích chuyển hướng.
   - Kiểm tra nguồn gốc chéo (Cross-Origin / CORS): Gửi request kèm header `Origin: https://malicious-attacker.com` ➔ Xác minh trả về HTTP 403 Forbidden (`FORBIDDEN_ORIGIN`), không bao giờ cấp `Access-Control-Allow-Origin: *` hoặc chấp thuận origin độc hại.

2. **Kiểm định Dữ liệu Đầu vào & Giới hạn Biên (A04 Boundary Verification):**
   - JSON body dị dạng (malformed JSON) ➔ Trả về HTTP 400 Bad Request với envelope JSON chuẩn `{ error: { code: 'BAD_REQUEST' | 'INVALID_JSON', ... } }`, tuyệt đối không lộ stack traces hay đường dẫn tệp hệ thống trên đĩa (`C:\...`).
   - Query `/api/dictionary` với `offset < 0`, `limit` không phải số, `limit > 100`, hoặc thiếu cả `q` lẫn `id` ➔ Trả về HTTP 400 Bad Request kèm thông báo lỗi rõ ràng.
   - Payload ngoại cỡ (> 100KB) ➔ Trả về HTTP 413 Payload Too Large.
   - Phương thức HTTP không hợp lệ (ví dụ `DELETE /api/health`, `POST /api/health`, `DELETE /api/dictionary`) ➔ Trả về HTTP 405 Method Not Allowed.

3. **Bảo mật Tệp Tĩnh & Chống Duyệt Thư mục Trái phép (Directory Traversal Defense):**
   - Gửi request `GET /../.env`, `GET /%2e%2e/.env`, `GET /assets/..%2f..%2f.env` ➔ Bị chặn đứng với HTTP 403 Forbidden, không bao giờ để lộ tệp cấu hình môi trường hoặc secrets.
   - Gửi request tới tuyến API không tồn tại (`GET /api/non-existent-api-route`, `GET /api/does-not-exist`) ➔ Bắt buộc trả về HTTP 404 với `Content-Type: application/json; charset=utf-8` và envelope `{ error: { code: 'NOT_FOUND', ... } }`, tuyệt đối không bị SPA HTML fallback chiếm đoạt.
   - Gửi request tới tuyến trang web thông thường (`GET /review`) ➔ Phục vụ SPA `index.html` với HTTP 200 `text/html`.

4. **Kiểm định Máy chủ Production Thực tế (PROD-01 & DICT-02 Verification):**
   - Khởi động máy chủ độc lập trên cổng động hoặc cổng kiểm thử.
   - `GET /api/health` ➔ Trả về HTTP 200 JSON khớp hoàn hảo schema `HealthResponse`, xác nhận `dictionary.loaded: true` và `dictionary.totalEntries: 122596`.
   - `GET /api/dictionary?q=學生` ➔ Trả về HTTP 200 JSON, kết quả xếp hạng Tier 1 chính xác với chữ Hán phồn thể `學生`, định nghĩa tiếng Việt đầy đủ và `source: 'database'`.
   - `GET /api/conversation` ➔ Trả về HTTP 200 JSON trạng thái sẵn sàng (`status: 'ready'`).
   - Kiểm tra chu trình sống tắt máy chủ sạch sẽ (Clean Shutdown): Đóng server không để lại lingering sockets hay unhandled handles.

### 2.2 Reusable Conforming Test Server Harness (`tests/fixtures/api/test-server.ts`)
- Khởi động một máy chủ HTTP chuẩn `node:http`.
- Tự động nạp trước động cơ từ điển CC-CEDICT (`dictionaryEngine.init()`) đảm bảo sẵn sàng 122.596 mục từ.
- Kiểm tra sự hiện diện của `server/app.ts` (do Subagent A02 bàn giao). Nếu có, ủy quyền trực tiếp cho `handleApiRequest` để kiểm thử mã nguồn production. Nếu chưa, kích hoạt bộ dispatcher mô-đun dùng chung.
- Cơ chế **In-Memory Stream Dispatch (`dispatchInMemory`)**:
  - Giải quyết dứt điểm rào cản chính sách bảo vệ mạng trên môi trường sandbox Windows (nơi các kết nối TCP loopback `connect` tới cổng ngẫu nhiên có thể bị chặn với mã lỗi hệ thống `EACCES`).
  - Sử dụng trực tiếp `IncomingMessage` và `ServerResponse` chuẩn của Node.js, truyền dữ liệu qua duplex streams với đầy đủ headers, status code và body buffers.
  - Nhờ đó, bài test chạy với tốc độ cực nhanh (~1ms mỗi request), 100% độc lập, không phụ thuộc vào trạng thái mạng bên ngoài.
- Thiết lập chroot jail nghiêm ngặt: Kiểm tra `resolvedPath.startsWith(normalizedDist)`, chặn đứng mọi yêu cầu chứa `..`, `%2e%2e`, hoặc `.env` với mã lỗi HTTP 403 Forbidden.

   - `1.8`: Từ chối các request cross-origin từ origin độc hại với HTTP 403 Forbidden; không cấp wildcard `*`.

2. **Phần 2: Dictionary Search Endpoint (`GET /api/dictionary`):**

4. **Phần 4: Missing Routes Isolation (`/api/does-not-exist`):**
   - `4.1`: Trả về HTTP 404 JSON với `{ error: { code: 'NOT_FOUND', ... } }`, xác minh không chứa mã nguồn HTML.
   - `4.2`: Trả về HTTP 404 JSON cho đường dẫn lồng nhau không tồn tại `/api/v2/nested/missing`.
5. **Phần 5: Clean Server Shutdown Lifecycle:**
